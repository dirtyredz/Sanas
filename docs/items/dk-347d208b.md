# A Start that fails at transcription leaves an empty ended meeting carrying the typed context

From the v0.1.18 build report: a Start that fails (e.g. STT can't connect) leaves an ended, empty meeting row as before, but it now carries the typed meeting context, which could block a later merge with another meeting that has context (merge allows at most one part with context). Consider deleting empty failed-Start meetings or not counting their context.
