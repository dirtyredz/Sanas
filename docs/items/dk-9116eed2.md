# Capture screen during meetings: explain the shared screen and diagnose visible code errors


Add an explicit **Capture screen** action (overlay button + configurable Ctrl+Shift+S) during live or
paused client/team meetings. It screenshots the display under the overlay, sends it once (in memory
only) with the meeting context to the assistant through `AssistantProvider`, and answers. For visible
code problems the answer names the visible error, the likely cause, a minimal fix in one code block and
a verification step. The Ctrl+Shift+K composer gains **Attach screen / Replace / Remove** with a
thumbnail of the in-memory draft.

Spec: `docs/plans/screen-capture.md`, sections 1-7 as amended by section 8 (owner scope cut, 2026-10-31):
no image persistence, no schema change, no lane-reservation machinery, no image replay for More detail.

## Acceptance

- Capture/attach work during live and paused meetings; busy/unavailable is refused before acquisition.
- Image bytes, desktop capture and the provider call stay in main; renderer gets only bounded
  thumbnails through validated IPC with main-issued draft tokens.
- Overlay content protection stays unconditional; overlay CSP allows only `img-src 'self' data:`.
- Fast gate green; packaged smoke still passes startup.
