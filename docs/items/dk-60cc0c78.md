# Evaluate semantic endpointing (Flux) for turn completion


Turn completion today is acoustic: Deepgram endpointing (600 ms) / UtteranceEnd (1000 ms) plus a 350 ms continuation grace and a 1.8 s fallback (services/turns/turn-assembler.ts). A long mid-sentence pause can still split one intent into two turns. Evaluate semantic endpointing (for example Deepgram Flux end-of-turn) against real meetings: latency to a completed turn, split rate, and cost. Follow-up to dk-f004d957.
