# Show the meeting's job/client in the overlay header


The overlay header could show which job/client the live meeting belongs to, so the owner can tell at a glance which client context Sanas is answering for.

Deferred from the overlay redesign (docs/plans/overlay-redesign.md, section 7 and 8): the overlay has no reliable job name today, and inferring it from stale UI selection is wrong. Needs an explicit main-process data contract (meeting -> job name in MeetingState or a typed IPC) before any UI.
