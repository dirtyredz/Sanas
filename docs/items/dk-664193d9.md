# Job memory from past meetings + relevant past-meeting retrieval in live answers


Owner decision 2026-10-29: "Memory + search".

## What
1. **Job memory** — per job, a separate section from the owner's Notes, hard-capped (~3,000 chars). After each meeting the AI *rewrites* it (merge, dedupe, drop stale; never append): decisions, open items, commitments + owners, numbers, what changed. Owner sees a proposed update on the job page and approves/edits before it's saved. Included in the cached system prompt for that job.
2. **Retrieval at answer time** — on Answer now (and for ambient answers when the turn names something specific), FTS5-search the job's past transcripts/summaries (same machinery as Ask-your-history) and add the top 2–3 snippets, bounded, to the user turn — not the cached system prompt.
3. **Context size meter** on the job page (Notes + memory + glossary), warn when large.

## Why
Owner wants past meetings to make answers smarter but is concerned about too much info in context. Capped curated memory + on-demand retrieval keeps always-on context small.

## Sequencing
Start after the turn-detection + Next point coach build lands (both touch assistant prompts and meetings orchestration).
