# Unify overlay resize clamp with overlay-bounds and extract overlay placement


Found in the structure review of c951bd3 (overlay fitted to connected displays), 2026-11-01.

- `resizeOverlay` in `src/main/windows/overlay-window.ts` (around lines 117-130) clamps the overlay to the work area with its own inline arithmetic and uses `getDisplayMatching`. `src/main/windows/overlay-bounds.ts` (`fitOverlayBounds`) owns the same "keep the overlay on a display" rule with a header-visibility test. Two definitions of on-screen will drift apart.
- `overlay-window.ts` (~188 lines) now mixes window lifecycle with about 40 lines of bounds handling: fit on create, re-fit on display change, debounced persist, resize.
- Cosmetic: the STRUCTURE.md ASCII tree comment for `windows/` does not mention overlay-bounds (the Layout bullet does).

Acceptance: move a pure resize clamp into `overlay-bounds.ts` and test it; move fit, reclamp, resize and persist into one overlay placement module that owns the display listeners and the save timer; `overlay-window.ts` keeps visibility, ghost and compose state. Keep `overlay-bounds.ts` Electron-free (its local `Rect` type is deliberate).
